# Hirofjet//HOME 安全设计差距与整改清单

- 依据：《全国互联网安全管理服务平台 自评估报告》（2026-11-10）
- 核查对象：`rhine-home` v2.5.5 当前代码
- 核查日期：2026-11-11
- 用途：对照自评估报告第 1–3 项，整理网站尚缺的安全设计；不构成法律意见，正式提交前建议由属地网安和法务复核。

## 一、先看结论

### 1. 报告与当前系统不一致的地方

以下项目不能只“写进报告”，需要先改代码或改正报告表述。

| 报告中的表述 | 当前实际 | 风险 |
| --- | --- | --- |
| Web 访问日志留存半年以上 | `access_logs` 只保留 30 天，且管理员可逐条或全部删除 | 报告失实；无法满足日志留存义务 |
| 系统记录用户操作、网络源地址/目标地址、端口、客户端特征 | 只有 Forum 3D 页面主动写入的少量浏览记录，字段只有模块、目标、IP | 缺少完整请求日志、目标地址、端口、UA/设备特征 |
| 已建立投诉举报机制 | 站内没有举报入口、工单、受理状态；仅有 GitHub Issues 联系 | 用户无法在站内举报，报告与事实不符 |
| 私信后续增加监管措施 | 私信目前只有好友限制、发送限流；无关键词过滤、举报、管理员取证、封禁联动 | 私信是高风险违法信息传播通道 |
| 用户发布信息可人工审核 | 主题帖非管理员默认待审；**回复自动通过**；留言板匿名可发；私信不过滤 | 评论区、留言板、私信存在审核缺口 |
| 注册信息永久留存 | 昵称、性别、头像、生日、简介等无保留期限设计 | 与最小必要、删除权冲突 |
| 用户可查看其他用户的性别、生日 | 公开资料接口对非本人隐藏性别、生日 | 报告描述不准确，或应改成“仅本人/管理员可见” |
| 系统记录用户订单 | 当前没有订单业务 | 报告疑似模板残留，应删除 |
| 网警可直接登录检查 | 当前只有超级管理员/管理角色，无监管只读账号、时限、IP 白名单、独立审计 | 无法证明“最小权限、可追溯” |

### 2. 已有基础

- 密码使用 `scrypt` 哈希；会话 token 使用随机值并存 MySQL。
- 注册邮箱验证码注册，发帖/回复要求已验证邮箱。
- 管理端有角色、板块权限、封禁、主题审核、软删除。
- React 默认转义；3D Markdown 使用 `DOMPurify` 清理。
- 部分接口已有内存限流；SQL 基本使用参数化查询。
- 有 `SECURITY.md` 漏洞报告入口。

这些可以保留，但不能替代下面缺失的合规与安全设计。

## 二、P0：提交自评估报告前必须补齐

### 1. 日志与审计

> 实施状态：v2.5.6 已加入 180 天请求日志、SHA-256 前向哈希链审计、只读安全日志页和可信代理 IP；外部 WORM/异地归档仍需部署。

**现状**

- `access_logs` 保留 30 天，字段不足，且 `/api/admin/access-logs` 可删除。
- 没有请求级访问日志，没有管理操作审计，没有登录/权限/封禁/删帖审计。
- `trust proxy` 固定为 1，若源站可被直连，`X-Forwarded-For` 可被伪造。

**建议设计**

1. 新增 `request_logs` 中间件，至少记录：
   - 时间、request-id、用户 id/匿名 id；
   - HTTP 方法、路径、状态码、耗时；
   - 源 IP、源端口（可得时）、目标 Host/端口；
   - User-Agent、设备指纹摘要（不采集过度硬件特征）；
   - 失败原因/限流命中；
   - 不记录密码、token、验证码、完整 Cookie。
2. 新增 `security_audit_logs`：登录成功/失败、验证码、密码重置、权限/身份变更、封禁、删帖/隐藏、举报处理、数据导出/删除、监管访问。
3. 留存不少于 **180 天**；日志独立存储/独立账号，应用管理员不能删除；到期由归档任务处理。
4. 日志防篡改：追加写、按日归档、哈希链/对象存储 WORM，至少保留异地备份。
5. 时间同步 NTP；日志时区统一。
6. 管理后台增加“安全中心 → 访问日志 / 审计日志 / 安全事件”，支持按用户、IP、时间、动作检索和导出。

**验收**

- 任意一次登录、发帖、删帖、改权限、封禁、举报处理都能在审计日志中还原“谁、何时、从哪、做了什么、结果”。
- 普通管理员无删除日志权限；日志保存 180 天后才可归档清理。

### 2. 投诉举报闭环

**现状**

- 没有 `content_reports`/`complaints` 表，没有站内入口；只有 GitHub Issues。
- 没有举报分类、受理编号、处理状态、申诉、时限。

**建议设计**

1. 全站增加“举报/投诉”入口：帖子、回复、私信、用户资料、留言板、图片。
2. 举报表单字段：对象类型/ID、链接、分类（违法有害、侵权、隐私、诈骗、骚扰、其他）、描述、证据截图、联系方式（可选）、是否匿名。
3. 生成工单号；举报人可凭工单号查询状态；站内通知处理结果。
4. 管理后台“举报处理”队列：待受理、处理中、已处置、已驳回、申诉中；记录处理人、理由、证据、时间。
5. 公布投诉举报方式：站内页面、专用邮箱，必要时电话；明确受理时限（建议 24 小时内响应、72 小时内初核、15 个工作日内办结）。
6. 增加申诉入口；被处置用户可提交申诉，二次复核。
7. 侵权/版权投诉单独分类，要求权属证明和反通知流程。
8. 紧急违法信息提供“立即下架/固定证据/上报”流程。

**验收**

- 任意用户无需登录即可找到举报入口和公开联系方式。
- 每条举报有编号、状态、处理记录和结果通知。
- 管理员不能无痕迹删除举报。

### 3. 私信与即时通讯监管

**现状**

- 仅好友可发私信；无限流外的内容审核、举报、管理员取证、关键词命中。
- 没有拉黑/屏蔽用户、消息举报、证据保全。

**建议设计**

1. 私信举报按钮；举报时保存上下文（前后若干条）并冻结，不让发送者删除。
2. 敏感词/链接/二维码/联系方式风险检测；高风险消息进入待审或延迟发送。
3. 管理后台私信检索需单独权限；查看即写审计日志；默认脱敏，仅案件关联时解密。
4. 用户拉黑/屏蔽、关闭陌生人私信、消息请求箱。
5. 封禁账号时同步禁止私信，并向对方展示“对方账号已受限”而不泄露原因细节。
6. 明确私信留存期限与隐私政策；监管调取需工单和审批。

### 4. 内容审核覆盖所有发布面

**现状**

- 主题帖默认待审，但回复自动 `approved`。
- 留言板允许匿名发表，只有 IP 限流。
- 用户资料、头像、图片附件、私信没有审核/过滤。
- 没有敏感词库、图片审核、外链风险提示、紧急停止开关。

**建议设计**

1. 回复改为“新用户/低信用待审 + 老用户先发后审”，或全部先审后发（按风险）。
2. 留言板：登录或验证码；敏感词过滤；人工审核队列；匿名也记录 IP/设备摘要。
3. 统一内容安全服务：文本敏感词、变体/拼音、URL/二维码、图片 OCR/NSFW、文件病毒扫描。
4. 新账号、低等级账号限制发帖/私信/上传频率；高风险内容转人工。
5. 管理后台增加“内容审核队列”，覆盖帖子、回复、留言、私信、头像、附件。
6. 增加“紧急停止”开关：一键关闭发帖/回复/私信/上传，保留只读。
7. 所有处置记录理由、证据、操作人、复审人；封禁/删除支持申诉。

### 5. 上传与文件安全

**现状**

- `/api/upload` 接受任意扩展名，最大 500 MB，按原扩展名保存到公开 `/uploads`。
- 没有 MIME/magic bytes 校验、图片重编码、病毒扫描、EXIF 清理、私有文件鉴权。
- 若上传 `.html`/`.svg`，同源静态访问可能形成存储型 XSS。

**建议设计**

1. 按用途白名单：头像/照片仅 JPEG/PNG/WebP/AVIF；视频 MP4/WebM；附件 PDF/ZIP/文档白名单。
2. 校验 magic bytes，不只信扩展名和 `Content-Type`。
3. 图片服务端重编码，剥离 EXIF/GPS；SVG 禁止或强制下载。
4. 上传文件放独立域名/对象存储，设置 `Content-Disposition: attachment`、`X-Content-Type-Options: nosniff`，禁止执行脚本。
5. 文件大小按类型限制；上传限流；病毒扫描；失败隔离区。
6. 私密附件使用签名 URL/鉴权下载，不暴露可枚举路径。
7. 保留上传审计：上传者、IP、文件哈希、大小、用途、扫描结果。

### 6. 管理账号与监管配合

**现状**

- 超级管理员权限过大；没有 MFA、没有只读监管角色、没有登录设备管理。
- 管理员操作没有完整审计。
- 报告称“网警可直接登录”，但没有专用账号设计。

**建议设计**

1. 超级管理员强制 MFA（TOTP/WebAuthn）。
2. 新增 `regulator_readonly` 角色：只读、限时、IP 白名单、水印、禁止导出原始密码/token。
3. 监管访问必须绑定工单：单位、人员、事由、范围、期限、批准人。
4. 提供“监管数据包”：账号信息、发布内容、日志、举报记录；生成哈希和交接单。
5. 监管账号所有操作单独审计；到期自动失效。
6. 禁止共享超级管理员账号；管理员登录异常告警。

### 7. 备案与公开合规信息

**现状**

- `src/content/legal.ts` 中 ICP 备案号、公安联网备案号、接入商、备案日期仍是占位。
- 页脚没有安全负责人/投诉举报专用联系方式。

**建议设计**

- 完成 ICP 备案和公安联网备案后，在页脚、`/legal` 页展示备案号并链接官方查询页。
- 公布网站安全负责人/投诉举报联系人（至少专用邮箱），与自评估报告保持一致。
- 保留备案材料、评估报告、整改记录和年度复核记录，版本可追溯。

## 三、P1：上线后 2–4 周内补齐

### 8. 真实身份与账号安全

- 当前仅邮箱验证。邮箱不能等同于“真实身份”。
- 对发帖、私信、举报等公共功能，建议至少手机号验证；高风险功能可要求实名信息。
- 若不做实名，报告中不能写“确保用户身份真实性”，应改为“邮箱验证 + 风险控制”，并限制未验证用户公开发布。
- 记录验证方式、验证时间、验证渠道；不要保存完整身份证影像，除非有明确法定依据和加密隔离。
- 密码策略：最少 8–10 位、常见弱密码库、禁止与用户名/邮箱相同；管理员更强。
- 登录失败：账号+IP 双维度限流、渐进延迟、验证码；异常登录通知。
- 会话：`HttpOnly + Secure + SameSite` Cookie 或短期 access token + 刷新；会话列表、单设备下线、改密全端失效。
- 邮箱验证码：`crypto.randomInt` 替代 `Math.random`；验证最多 5 次；验证接口限流；重置密码统一返回模糊提示，避免枚举邮箱。
- 注册/登录加人机验证（Turnstile/hCaptcha）；拦截一次性邮箱。
- 账号注销、封禁申诉、登录设备管理。

### 9. 个人信息保护

- 增加《隐私政策》《用户协议》《社区规范》，注册时主动勾选并记录版本、时间、IP。
- 建立个人信息清单：字段、目的、公开范围、保存期限、共享对象。
- 最小化：生日、性别默认不公开；昵称/简介/头像提供可见范围设置。
- 数据主体权利：访问、更正、导出、删除、注销、撤回同意。
- 账号注销：15 个工作日内删除或匿名化；法律要求留存的日志/交易记录单独说明。
- 未成年人保护：年龄识别/监护人同意、默认私密、限制私信和打赏/付费功能。
- 图片 EXIF 清除；日志脱敏；数据库/备份加密；敏感字段列级加密。
- 数据泄露应急预案：发现、遏制、评估、通知、复盘。

### 10. Web 与接口安全

- 全站 HTTPS，HTTP 301；HSTS；TLS 1.2+。
- 安全响应头：CSP、`X-Content-Type-Options`、`X-Frame-Options/frame-ancestors`、`Referrer-Policy`、`Permissions-Policy`、`Cross-Origin-Opener-Policy`。
- 管理后台单独域名/路径 + IP 白名单/零信任；后台禁止被搜索引擎索引。
- CORS 白名单；不要对任意来源开放凭据。
- `trust proxy` 仅在可信反代后启用，限制可信代理 IP，避免伪造 IP。
- 限流从单机内存改为 Redis/WAF；覆盖登录、验证码、注册、重置、上传、举报、私信、搜索。
- 依赖漏洞扫描、SAST/DAST、密钥扫描；CI 中执行。
- WAF/DDoS/CC 防护；源站不直接暴露。
- 备份：数据库+上传目录每日备份、异地、加密、定期恢复演练。
- 监控告警：5xx、登录爆破、上传异常、举报积压、磁盘/证书到期。
- 漏洞披露政策更新版本号；安全事件联系人和响应时限。

## 四、P2：1–3 个月内完善

- 通过等级保护测评或至少按等保二级要求做差距整改（若属地要求）。
- 年度安全评估复核；功能重大变更重新评估。
- 渗透测试与修复闭环。
- 管理员/版主安全培训与保密承诺。
- 内容审核员培训、考核、排班和应急联系人。
- 供应商/云服务安全评估与数据 processing 协议。
- 业务连续性演练：数据库故障、文件丢失、账号被盗、舆情事件。
- 安全运营报表：举报量、处置时长、封禁量、登录攻击、漏洞修复 SLA。

## 六、提交报告前的表述修正建议

在完成上述整改前，建议把报告改为“已实现/建设中/后续计划”三态，不要提前承诺：

1. “Web 访问日志留存半年以上” → 改为实际保留期限，或先实现 180 天再写。
2. “已建立投诉举报机制” → 改为“已设 GitHub Issues 联系渠道，站内举报工单建设中”，完成后再写已建立。
3. “私信后续增加监管措施” → 明确当前未上线监管能力，不能作为已具备措施。
4. “用户可查看其他用户性别、生日” → 改为“仅本人及管理员可见”，与代码一致。
5. “系统永久记录订单” → 删除，当前无订单业务。
6. “网警可直接登录” → 改为“可依申请提供只读监管账号/数据导出”，并上线审计。
7. “所有用户邮箱注册确保身份真实” → 改为“邮箱验证 + 风险控制”，不要等同于实名。
8. “注册信息永久留存” → 改为“按隐私政策保存，注销后删除/匿名化，法定日志除外”。
