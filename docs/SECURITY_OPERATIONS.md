# 安全运营手册

适用版本：`2.6.x`  
更新时间：2026-11-11

## 1. 安全响应头

服务端已统一设置：

- `X-Content-Type-Options: nosniff`
- `X-Frame-Options: SAMEORIGIN`
- `Referrer-Policy: strict-origin-when-cross-origin`
- `Permissions-Policy: camera=(), microphone=(), geolocation=(), payment=(), usb=()`
- `Cross-Origin-Opener-Policy: same-origin`
- `Content-Security-Policy`：限制脚本、样式、图片、媒体、字体、连接、iframe 与表单目标
- HTTPS 请求或生产环境：`Strict-Transport-Security: max-age=31536000; includeSubDomains`

部署后检查：

```bash
curl -I https://你的域名/
```

CSP 当前允许 `unsafe-inline` 以兼容现有前端资源；后续可将内联样式/脚本逐步外置，再收紧 CSP。

## 2. 限流与 WAF

- 应用内已有全局 API 限流（每 IP 300 次/分钟）；
- 登录、验证码、注册、密码重置、举报、私信、发帖另有细粒度限流；
- 生产环境建议在 Nginx/Cloudflare 增加：
  - CC 防护与连接数限制；
  - 登录/注册路径更严格限流；
  - 恶意 UA、扫描器、异常路径拦截；
  - 上传大小与超时限制；
  - 仅允许站点域名 Host，拒绝直接 IP 访问。

Nginx 必须传递：

```nginx
proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
proxy_set_header X-Real-IP $remote_addr;
```

Node 只监听内网/回环，`TRUST_PROXY=loopback`；不要让 3001 端口直接暴露公网。

## 3. 备份与恢复

新增 `scripts/backup.mjs`：

```bash
cd /path/to/rhine-home
BACKUP_DIR=/srv/backups/rhine-home node scripts/backup.mjs
```

要求：

- 数据库与 `uploads/` 每日备份；
- 备份目录与站点分离，不能放在 `public/` 或 `uploads/`；
- 备份加密/权限限制；
- 至少保留 7 个日备、4 个周备、3 个日备；
- 每季度做一次恢复演练；
- 将 `manifest.json` 的 SHA-256 与备份文件一起保存。

恢复前先停止写入，校验 manifest，再恢复数据库与上传目录。

## 4. 监控与告警

建议监控：

- `/api/health` 可用性与响应时间；
- 5xx、429、登录失败次数；
- 举报积压与处理时长；
- 上传/磁盘使用率；
- TLS 证书到期；
- 数据库连接数、慢查询；
- 备份是否按计划生成。

告警通道至少一个独立于站点的渠道（邮件/IM/短信）。安全事件处理见 `SECURITY.md`。

## 5. 隐私与数据请求

- 用户可在「个人资料 → 账号 → 隐私与数据」导出数据；
- 用户可输入密码与 `DELETE` 确认注销；
- 注销会删除会话、通知、私信、留言、关注/屏蔽，匿名化公开内容与举报人信息；
- 安全日志、访问日志按法定义务保留，不因注销删除；
- 管理员不得绕过流程导出或传播个人信息；
- 数据请求处理记录应保留：请求时间、身份核验方式、处理结果、操作人。

目标时限：

- 查询/更正：15 个工作日内；
- 导出/注销：15 个工作日内；
- 安全事件通知：发现后 24 小时内初判、72 小时内通知受影响用户（法律另有要求除外）。

## 6. 年度安全评估与等保

建议建立年度计划：

1. 每年至少一次自评估复核，功能重大变更后重新评估；
2. 每年一次渗透测试，重点：认证、权限、越权、上传、CSRF/XSS、注入、日志；
3. 按属地要求开展等级保护备案/测评；
4. 管理员、版主年度安全与内容审核培训；
5. 备份恢复演练、账号被盗演练、违法信息处置演练；
6. 漏洞修复 SLA：严重 24 小时、高 72 小时、中 7 天、低 30 天；
7. 评估报告、整改记录、培训签到、演练记录归档至少 3 年。
